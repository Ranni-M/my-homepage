2026.04.12 · 工程习惯

用 AI 生成首版后，我先删掉了一半样式

AI 生成的页面「能看」，但那股默认味儿很重：通用蓝、通用圆角、通用阴影。第一版我直接拿来当成品，结果同学一眼就看出是模板。

  • 反过来做：先定三个变量——背景色、主色、正文色，其余颜色都由它们推。
  • 删掉一半不必要的东西后再谈加法：去掉多余阴影、去掉渐变、统一圆角成两个档位。
  • 每轮只改一类事，改完立刻在浏览器刷新验收，不满意就 git checkout 退回。

2026.03.28 · 前端

从 300 行到 180 行：一次渲染逻辑重构

记账本最初每加一条记录就往页面里 append 一个节点，记录一多，滚动明显发涩。

  • 问题定位：读一遍自己的代码，发现「读数据—拼 DOM—写页面」三步混在一个函数里。
  • 改法：拆成「取数据 / 拼字符串 / 一次性写入」，再加一个 renderAll 统一入口。
  • 顺手的收获：一次性写入天然支持空状态——没有记录时直接渲染一句「这周还没记账」。
  • 教训：先让它能跑，再让它好读，最后才谈快。顺序反了会一直卡在细节里。

2026.03.05 · 部署

GitHub Pages 上线踩过的 5 个坑

第一次把站点推上去，打开 URL 是一片空白，那一刻比写代码本身更让人上头。

  • ① 首屏空白：先看文件名大小写，Index.html 和 index.html 在 Pages 上是两个东西。
  • ② 样式全丢：查 link 标签的 href 路径，能相对就别写绝对路径。
  • ③ 图片不显示：图片必须在仓库内，本地磁盘绝对路径（D:\...）线上必然失效。
  • ④ 404 延迟：首次发布要等 1–2 分钟，别急着改配置。
  • ⑤ 分支选错：Source 要选 main + / (root)，改完记得 Save。

2026.02.20 · 数据

localStorage 到底能装多少？我压了一次

记账本把数据全放在 localStorage，一次和同学聊天被问「存满了怎么办」，发现自己答不上来。

  • 实测：一条记录约 120 字节，几千条毫无压力；真正会先出问题的是写入频率，不是容量。
  • 教训：每次操作都整体序列化再写回，短期没事，长期该做增量与节流。
  • 所以加了「导出 JSON」按钮——数据在用户手里，比存在我这里更让人放心。

2026.01.15 · 响应式

响应式不是加个媒体查询就完事

把窗口拉窄才发现：字没溢出，但整个页面能左右滑动——一个看不见的横向滚动条。

  • 排查顺序：先找宽度写死的元素，再找 padding + 100% 宽度凑出来的溢出，最后才怀疑文字。
  • 有用的两行：overflow-wrap: break-word 和把固定宽度换成 max-width。
  • 验收标准定成「375px 下 scrollWidth 等于 innerWidth」，比「看着还行」靠谱得多。
  • 顺带把导航改成汉堡菜单，窄屏终于不用挤六个字。

2025.12.08 · 方法

我是怎么把 AI 当结对伙伴用的

半年下来最大的体会：AI 最擅长的不是替我做决定，而是把我模糊的想法翻译成可执行的步骤。

  • 描述问题时用「区域 + 现状 + 期望」三句话，配上截图，比写十行长句有效。
  • 让它解释代码，而不是只让它改代码——看懂之后再自己动手改一遍。
  • 事实类内容（成绩、经历、链接）永远自己核对，AI 编得比谁都像真的。
  • 每次改动都提交一次，改砸了随时退回，这才敢放心大胆试。
